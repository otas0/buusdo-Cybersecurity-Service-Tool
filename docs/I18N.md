# Internationalisation (website)

buusdo Cybersecurity Service Tool ships a multi-locale website UI. Extension / desktop packs follow later; website is first.

## Shipped regions

| Region | Locales |
|--------|---------|
| Global | `en` |
| East Asia | `zh-Hans`, `zh-Hant`, `ja` |
| Europe | `pt-PT`, `pt-BR`, `de`, `fr`, `es`, `it`, `nl`, `pl`, `sv`, `da`, `fi`, `nb`, `el`, `cs`, `sk`, `hu`, `ro`, `bg`, `hr`, `sl`, `lt`, `lv`, `et`, `ga`, `mt`, `uk`, `is`, `ca` |
| Southern Africa | `af`, `zu`, `xh`, `nso`, `st`, `tn`, `ss`, `ve`, `ts`, `nr` (EN under Global) |
| Pacific | `mi` (te reo Māori) |
| Southeast Asia | `id`, `ms`, `th`, `vi`, `fil`, `km`, `lo`, `my` |

Catalog source: [`i18n/locales.ts`](../i18n/locales.ts). Routes: `/{locale}`, `/{locale}/settings`, `/{locale}/privacy`, `/{locale}/lists-offline`.

## Message bags

| Layer | Location | Coverage |
|-------|----------|----------|
| English (canonical) | `i18n/messages.ts` → `en` | Full (~308 keys) |
| Portuguese (Portugal) | `i18n/messages.ts` → `pt-PT` | Full |
| Full packs | `i18n/packs/zh-Hans.json`, `zh-Hant.json`, `ja.json` | Full |
| Core packs | `i18n/packs/{id}.json` | Chrome + Halt path (`i18n/core-keys.ts`); rest falls back to EN |
| Brazil | `pt-BR` pack overlays `pt-PT` | Core (or more) |

`getMessages(locale)` = normalize → merge pack onto EN (or pt-PT for `pt-BR`).

## Language switcher

Header `<select data-testid="locale-select">` grouped by region (`components/LanguageSwitcher.tsx`). Hash on Settings / Privacy is preserved when switching.

## Extend a pack

1. Edit or add `i18n/packs/{id}.json` (UTF-8). Keep placeholders `{ms}`, `{tag}`, `{source}`, …
2. Run `npm run gen:pack-index` (rewrites `i18n/pack-index.ts`).
3. Run `npm test -- tests/i18n-locales.test.ts`.
4. Spot-check `/{id}` and Halt copy.

To promote a locale from core → full: translate every key in `_en.snapshot.json` into that pack (same key set as EN).

## Aliases

`normalizeLocale` maps common tags (`zh` → `zh-Hans`, `zh-TW` → `zh-Hant`, `pt` → `pt-PT`, `jp` → `ja`, `tl` → `fil`, `no` → `nb`). URL path segments must be exact catalog ids.

## Out of scope (for now)

- Extension toast / desktop `i18n.js` still EN + pt-PT (sync later).
- China Pages remain 中文 / EN static pair (`china-pages/`), separate from Workers locale routes.
