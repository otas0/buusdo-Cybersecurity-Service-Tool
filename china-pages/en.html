Notice

Full checking is not offered on mainland China networks

Bottom line: For mainland China network conditions, this Project does not offer or promise full website checking. Do not rely on https://buusdocst.mtsu.workers.dev — that host often cannot connect from the mainland, and cannot automatically send you here.

Cannot open Workers (timeout / endless spinner) is expected — that is not a “redirect still loading”; the request never reaches Cloudflare. Open this notice via its own URL or the poster QR; do not wait for workers.dev to bounce you here.

Dear users,

Thank you for your interest in buusdo Cybersecurity Service Tool (the “Project”). This notice explains the mainland China service arrangement.

1. Reason and scope

Full checking runs on Cloudflare Workers ( https://buusdocst.mtsu.workers.dev ). On some mainland China networks that host is slow, times out, or unreachable. Therefore:

  • Mainland users should treat this notice as the only official explanation entry ( https://otas0.github.io/buusdocst/ ).
  • From 22 November 2026 that entry keeps only this notice (explainers / privacy summaries / install guides offline).
  • From 23 November 2026: if a visitor can reach Workers and Cloudflare marks them as mainland China ( CF-IPCountry=CN ), HTML is force-redirected here so an unstable network is not mistaken for a working checker. /api/* is never redirected.
  • If mainland TCP cannot reach Workers: no redirect runs — that is why you must bookmark or scan this page’s URL.

Scope targets mainland China network conditions; it does not mean Workers is unavailable on every network worldwide.

2. How the two entries work together

There are two related entry points:

  • China mainland entry — https://otas0.github.io/buusdocst/ (this notice; mainland visitors are force-sent here from Workers)
  • Workers full checker — https://buusdocst.mtsu.workers.dev (product UI; e.g. /zh-Hans, /zh-Hant, /en)
  1. Mainland readers : this notice is the only official explanation entry; full checking is not offered — do not wait for workers.dev to redirect.
  2. If Workers is reachable and Cloudflare marks CN : HTML is force-sent back here (ops opt-out: ?china_workers_stay=1).
  3. Only on non-mainland, Cloudflare-reachable networks do the “Open full checker” buttons below matter; mainland readers can ignore them.

3. Network detection and privacy

  • On Workers : Cloudflare CF-IPCountry (only to decide the force-redirect — not for profiling or ads).
  • On this page : browser GET /api/health to Workers (short timeout, no cookies) to show reachability — no auto-redirect.
  • Does not call : /api/check (that runs only after you open Workers and submit an address).
  • Language preference : 中文 / EN choice stays in local localStorage (buusdocst-china-lang) only — not uploaded.

Full privacy policy (on Workers — non-mainland / Cloudflare-reachable networks only ; mainland readers should rely on this notice): https://buusdocst.mtsu.workers.dev/en/privacy. From the mainland that link often times out or returns here.

4. Restoration

Restoration of the China entry is not scheduled. When conditions allow, a new notice will be published. Until then the Project makes no promise about mainland reachability of the entry pages or Workers.

5. Contact

If you are on a Cloudflare-reachable network but cannot open Workers, or have questions about this notice, contact us via GitHub Issues. We apologise for the inconvenience and thank you for your understanding.
